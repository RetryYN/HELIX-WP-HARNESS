# L1 企画書 — 完全自走型 WP 運用 HARNESS

- 位置づけ: HELIX V モデルの L1 企画（フリー形式）。L2 要求の入力（目的・対象・価値仮説・採用境界）。
- 状態: **draft**（PO 確認前。confirm は PO の明示判断で行う）
- 日付: 2026-08-21

## 目的

WordPress サイトの運用（コンテンツ投稿・更新・計測・改善のループ）を、人間の
判断ポイントを承認ゲートに限定した上で **AI エージェントが完全自走**で回せる
ハーネスを作る。人間（PO）は方針と承認だけを持ち、日々の運用作業を持たない。

## 対象・非対象

| | 内容 |
| --- | --- |
| 対象 | WordPress 媒体の運用一式（投稿・更新・テーマ連携・計測取得・改善提案・再実行） |
| 対象 | **既存サイトの引継ぎ**（現状把握→運用移管）と**新規サイトの立ち上げ**（環境構築→テーマ適用→初期コンテンツ→運用開始）まで |
| 対象サイト | HELIX 経由で運用する自社サイト。**検証も本番サイトで行う**（PO 判断 2026-08-21。専用検証環境は前提にしない） |
| 非対象 | WP 以外の媒体（X ほかは別リポの別ハーネス）。WP テーマ自体の開発（HELIX-WP-THEME 側の責務） |
| 非対象 | 第三者への配布・汎用パッケージ化 |

## 価値仮説

- 運用の人手コストがゼロに近づけば、サイト数・更新頻度をスケールさせても運用負荷が増えない。
- 判断を承認ゲートに集約することで、完全自走でも品質・安全（誤投稿・事故書込み）を
  fail-close で守れる。
- 運用ループ（投稿→計測→改善）を機械証跡で回すことで、改善が勘でなく evidence 駆動になる。

## 採用境界（すでに出ている PO 判断・上流制約）

1. **開発規律は HELIX コア（HELIX Lite）を継承**する。resident lanes / routing /
   allocation / 配布系は本家 HELIX-HARNESS で育て、本リポへ複製しない。
2. **進行順序は PoC → 要求 → 設計 → 実装**。実機証跡なしに先へ進まない
   （既存 PoC: XServer API 証跡 2026-08-14）。
3. **外部 write 境界**: 本番サイトへの write は承認ゲートを通す（自走段階に応じてゲート粒度を
   緩める。credential を repository・DB・ログへ書かないのは不変）。検証は本番サイトで行ってよい
   （PO 判断 2026-08-21 — 旧「Docker WP のみ」制約は本企画では採らない）。ただし破壊的操作
   （削除・上書き・設定変更）はバックアップ・ロールバック手段の確保を実行条件とする。
4. **WP 接続は API 車線を第一候補**とする（WP は Application Password + REST で
   API を用意しやすい媒体として選定 — 旧 ADR-005 wp-rest-direct を legacy 参照）。
   ブラウザ車線は API で賄えない箇所の補完として検討する。
5. **テーマ連携**: 開発ベースは HELIX-WP-THEME（旧 AGENT-NEO）。AI 判定ロジックは
   ハーネス（オーケストレーター）側に置き、テーマ／プラグインは表示に徹する
   （REQ-NF-025 の分離原則を引き継ぐ）。
6. **統合層との関係**: 本リポは HELIX-MARKETING-HARNESS（統合層）の `media/wp/`。
   共通規律は統合層 CLAUDE.md が正本。

## 完全自走の到達段階（企画としての目標水準）

| 段階 | 内容 | 人間の関与 |
| --- | --- | --- |
| S1 | 指示駆動: PO の指示で個別運用タスクを実行し証跡を残す | タスクごとに指示 |
| S2 | 半自走: 運用ループを提案し、承認を得て実行する | 承認のみ |
| S3 | 完全自走: 承認ゲート付きでループを常時運転する | 例外時と方針変更のみ |
| S4 | 拡張: 既存サイトの引継ぎ・新規サイトの立ち上げを自走で実行できる | 引継ぎ/立ち上げの発注と承認 |

企画のゴールは S3、拡張目標が S4（引継ぎ・新規立ち上げ）。L2 以降のスライスは S1 から積む。

## L2 への引き渡し

L2 要求では本書を入力に、利用者（PO）・対象範囲・非対象・期待結果・人間受入基準を
exact scope として確定する。最初のスライスは「S1 の最小運用タスク 1 本を PoC 証跡から
要求化する」ことから始める。
