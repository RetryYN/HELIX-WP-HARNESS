# キーワード正規化・分類規則

- 状態: candidate
- 日付: 2026-08-23
- 適用範囲: サイト設計取り込み、DFS照合、記事KW群、SEOチェックゲート、施策UI

## 1. 処理順序

`原文保持 → 表記正規化 → SEO意味語化 → context root/語数ツリー → alias統合 → 同じroot内のSERP照合 → 記事KW群 → WP記事照合 → SEOゲート`

SEO意味語化の直後に全取込KWの語彙ツリーを生成する。同一term multisetは同一階層のalias、親のterm multisetへ
意味語を追加したKWは子とし、包含する実在KWのうち意味語数が最大のものを直近親にする。語数は階層生成に使うが、
同一施策への統合可否は後段のSERP照合で決める。例: `it 就活` → `it ニュース 就活` →
`就活 気になるニュース it`。この階層を作らず全KWを同じ記事照合フィルターへ投入しない。

語彙包含よりコンテキスト境界を優先する。`IT`は対象業界を固定する意味語なので、`就活`と`IT就活`は親子化せず
別ルートにする。IT文脈の子KWは親候補にも`IT`を必須とし、親探索時にコンテキスト語を脱落させない。

文字列の正規化と検索意図の判定を混同しない。原文、出典ファイルdigest、シート、行、DFS task、
raw snapshotは常に逆引き可能にする。

### 正本境界

- Excelは初回投入・差分取込の入力資料であり、運用正本ではない。
- 取込runが原文、provenance、`source_order`をDBへ保存し、以後の一覧・分類・状態・記事割当はDBを読む。
- Excelの再投入は既存行の直接上書きではなく、新しいimport版として差分を記録する。
- PO操作、DFS解析、WP記事ID照合はDBへ追記し、Excelへ逆書きしない。
- 一覧が「マップ順を踏襲する」とは、DBに取り込まれた`source_order`で並べることを意味する。

### サイト分離境界

- `site_id`をkeywords、カテゴリ割当、解析run、SERP判定、記事KW群、WP記事IDの必須キーとする。
- KW同一性はグローバルでなく`site_id + compact_normalized`の範囲で判定する。
- 親子化、alias統合、SERPクラスタ、施策件数、記事割当をサイト横断で実行しない。
- 同じ文字列が複数サイトに存在しても、戦略、カテゴリ、優先度、状態、記事群を共有しない。
- DFS raw snapshotの再利用可否は取得条件と鮮度で判断できるが、解析結果と施策判断はサイト別に記録する。
- UIはヘッダーで`site_id`を先に確定し、全機能タブと件数をそのサイトへscopeする。固定サイトは
  最大4件をタブ表示し、それ以上はサイト名・domainを検索できる「サイト一覧」から切り替える。

## 2. 正規化

用途別に次を併存させる。

| 値 | 処理 | 用途 |
| --- | --- | --- |
| raw | 無加工 | 出典・監査 |
| display_normalized | NFKC、小文字化、前後空白除去、連続空白を1個へ統一 | UI・通常比較 |
| compact_normalized | display_normalizedから空白除去 | 表記差・記事coverage照合 |
| ordered_terms | 複合語辞書を適用したSEO意味語列 | 語順の保持 |
| term_multiset | SEO意味語と出現回数を安定ソート | 語順違い候補の抽出 |

`it 就活サイト`、`it 就活 サイト`、`IT就活サイト`はcompact_normalizedが等しいため
`exact_alias`とし、別KWやmain/subとして数えない。

SEO意味語数は補助値として保持するが、空白区切り数や形態素数だけで親子・ロングテールを判定しない。
複合語（例: `就活サイト`、`就活エージェント`、`Webライティング`）を壊さない辞書を版管理する。
形態素解析器がひらがなを助詞・助動詞へ誤分割する既知語も辞書で先に正規化する。例:
`就活ねくたい` → `就活 | ネクタイ`（2意味語）。解析器の生の品詞結果を意味語数として無検証採用しない。

## 3. 関係分類

| relation | 定義 |
| --- | --- |
| exact_alias | 全半角・大小文字・空白等の表記差だけ |
| reordered_alias | SEO意味語の多重集合が同じで語順だけ異なる。同一正規化概念として先に統合し、各表記のSERP差は監査値として保持 |
| child | 親のSEO意味語を全て含み、意味のある修飾語が1語以上追加される |
| sibling | 親語または語彙は異なるがSERPsが近く、同一記事へ内包可能 |
| separate | SERP一致率60%未満 |
| unresolved | SERP上位5件未満、取得失敗、解析不能 |

語彙上の親子はSEO意味語の包含で候補化する。語順違いや親子候補だけでは統合を確定せず、
上位5 organic URLの照合結果を付ける。
親候補は修飾語付きKWを除外する。例えば`it 就活人気ランキング`の親を`it 就活 ランキング`にはせず、
非修飾語の実在祖先`it 就活`へ接続する。

## 4. SERP検索意図分類

`一致率 = 上位5件に含まれる共通URL数 / 5`

| 一致率 | confidence | 扱い |
| ---: | --- | --- |
| 80%以上 | high | 同一施策KW群へまとめる（高確度） |
| 60%以上80%未満 | possible | 同一施策KW群へまとめる（要監視） |
| 60%未満 | separate | 原則として別記事候補 |
| 双方または一方が5件未満 | insufficient | 自動統合しない |

順位の一致は要求せず、URL集合を比較する。比較URL、比率、取得条件、snapshot digestを保存する。

SERP一致率60%以上を同一施策KW群の境界とし、施策記事数は正規化・alias統合後のSERP群数とする。
ただし比較対象は同一`site_id`かつ同一context rootの代表KWに限定する。別root間はURLが重なっても
`context_separate`とし、同じ施策へ統合しない。
`high` / `possible`は群を分ける状態ではなく、群内のSERP証跡の確度として保持する。

連結成分だけでA≈B≈Cを推移統合するとAとCが不一致になり得るため、クラスタ統合は
**complete-linkage**とする: 2つのクラスタは、両クラスタの全メンバー対が一致率60%以上を
満たす場合に限り統合する（一致率降順・ID順の決定論マージ）。各辺のconfidenceをUIへ表示する。

## 5. 親KW・メインKW・修飾KW

### 親KW

子KWから検索シチュエーションを変える修飾語を除いたSEO意味語列とする。

例:

- 親: `it 就活サイト`
- 子: `it 就活サイト おすすめ`
- 子: `it 就活サイト 比較`

### メインKW

メインKWは単一の「単語」ではなく、検索クエリとして成立するトピック句とする。
同一施策KW群では検索Volが最大のmain候補を採用し、残りを`intent_keyword`として内包する。
ただし`おすすめ`、`比較`、`ランキング`、`口コミ`、`評判`、
`選び方`、`方法`等、検索シチュエーション・評価軸・行動を変える修飾語付きKWをメインKWにしない。
これらは`intent_keyword`（内包KW）として持つ。
修飾語判定は形態素トークン境界で行い、版管理された修飾語辞書のトークン列と最長末尾一致した場合のみ修飾語付きKWとする（`比較的`等の複合語を`比較`と誤認しない）。
修飾語付きKWだけでSERP群が成立した場合もmainへフォールバックさせない。語数ツリー上の実在親KWが
別SERP群にある場合は、SERP 60%境界を優先して親施策へ吸収せず、`derived_parent_candidate`として未確定にする。
親と同一SERP群になった場合だけ、修飾語KWを親mainの`intent_keyword`として内包する。
内包された修飾語KWに自サイト既存記事がタイトル一致する場合は、内包KW単位の担当記事証跡（`matched_role=intent`）として保持する。
この証跡は表示のみで、群の記事選定・`wp_article_id`更新には参加しない。既存記事の統合・リライトは別判断とする。

親クエリの導出では、版管理された修飾語辞書に一致する末尾修飾句だけを1段除去する。残った語句を
共通語集合へ縮約したり、さらに短い単語へ再帰的に切り詰めたりしない。

- `it 就活サイト おすすめ` → `it 就活サイト`（可。最長トピック句を保持）
- `ライター 副業`（main）← `記事作成 副業`（intent_keyword）。`副業`への縮約はしない
- `おすすめ it 就活サイト` → 語順alias/形態解析を先に行い、単純な先頭語削除では導出しない

導出した親クエリは、次のいずれかを満たす場合だけメインKWとして確定する。

1. DBへ取り込まれた入力KWとして実在する。
2. PO操作で親KWとして確定されている。
3. DFSで親クエリ自体を取得し、検索結果と計測値が成立している。

いずれも満たさない派生値は`derived_parent_candidate`に留め、`main_keyword`へ昇格させない。
SEO意味語数は記録するが、単語数だけでメイン可否を決めない。単一語でも実在クエリとして確認できれば
メインになり得る一方、複数語でも検索クエリとして成立しなければメインにしない。

修飾語付きKWは検索Volが大きくてもmain候補から除外する。修飾語を除くmain候補同士では検索Vol最大を
採用する。同値の場合は入力`source_order`が早いKWを採用し、決定を再現可能にする。

```json
{
  "main_keyword": "it 就活サイト",
  "intent_keywords": [
    "it 就活サイト おすすめ",
    "it 就活サイト 比較"
  ],
  "modifiers": ["おすすめ", "比較"],
  "intent_confidence": "high"
}
```

親KWが入力に存在しなくても子KWの共通意味語から`derived_parent`として生成し、出典となった子KWを
記録する。AIの自由生成ではなく、版管理された意味語解析と修飾語辞書から決定論生成する。

## 6. 施策判断と記事作成ゲートの分離

DFSデータは、記事を作る前の**施策判断**と、作成物を公開できるか判定する**記事作成ゲート**へ
分離する。同じ観測値を両方へ無条件に流用しない。

| DFSデータ | 施策時の用途 | 記事作成ゲート |
| --- | --- | --- |
| 検索Vol・月別推移 | main選定、優先度、季節性 | 使用しない |
| SERP URL一致 | 施策KW群と記事数の決定 | 対象KW群の取り違え検知 |
| AI Overview出現 | organic CTR低下リスクとして施策価値を補正 | 使用しない |
| CPC・競合性・SERP機能 | 商業性、難易度、organicクリック余地 | 使用しない |
| PAA・関連検索・競合見出し | 構成候補を作る入力 | 承認済み`required_topics`だけ検査 |

AI Overviewは「記事に含めるべき内容」ではない。出現有無と観測履歴をクエリ群ごとに保持し、
検索Volをそのまま施策価値とせず、organicクリック余地が著しく下がり得るクエリとして優先度、
期待クリック、施策採否の判断へ使う。単発観測と継続出現を区別し、記事公開の合否には使わない。

### PAA・関連検索からの内部リンク導出

PAAの質問文と関連検索KWは正規化後に同一`site_id`の施策KW群へ照合し、次のように処理する。

1. 照合先が同じ記事KW群なら、別リンクを作らず本文の`required_topic`候補にする。
2. 照合先が別の記事KW群なら、観測元記事から照合先記事への`internal_link_candidate`を作る。
3. 照合先にWP記事IDがあればリンク先URLを確定し、本文内で質問・関連語を説明する箇所を
   `source_section`としてリンク位置候補にする。
4. 照合先記事が未作成なら`waiting_for_target_article`として保持し、URLを捏造しない。
5. 照合先がなければ新規KW候補に留め、無関係な既存記事へ接続しない。

anchorはPAA・関連検索の文字列をそのまま完全一致で強制せず、リンク位置の文脈に合う自然な語句を
候補化する。候補は`source_article_id`、`source_section`、`trigger_type`、`trigger_text`、
`target_keyword_group_id`、`target_article_id`、根拠snapshotを持ち、サイト横断リンクを生成しない。

### 記事作成SEOゲート

- main_keywordはタイトル、主要見出し、本文で個別にcoverageを確認する。
- intent_keywordは完全一致の強制ではなく、修飾語が要求する内容構造を確認する。
  - `比較`: 比較軸と複数候補の比較がある。
  - `おすすめ`: 推薦対象と推薦根拠がある。
  - `ランキング`: 順位、評価軸、順位根拠がある。
- exact_alias/reordered_aliasを別KWとして重複カウントせず、不自然な語順の完全一致を強制しない。
- PAA・関連検索・競合見出しの全件を必須化しない。構成策定時に採用し、出典付きで固定した
  `required_topics`だけをcoverage対象にする。
- 承認済み内部リンク候補でリンク先WP記事IDが存在する場合は、指定`source_section`内に対象記事への
  リンクがあることを検査する。リンク先未作成の候補は公開ゲートをfailさせず待機状態にする。
- 欠落したmain、intent、必要構造を別々に返し、1件でも必須条件が欠ければfail-closeとする。

## 7. UI表示

一覧は1行=1施策KW群とし、main_keyword、main検索Vol、intent件数、実WPカテゴリー階層、AIO有無、
施策状態、WP記事IDだけを比較可能な列として表示する。intent_keywords全文、alias、親子・兄弟関係、
SERP一致数/率/confidence、共通・非共通URL、SEOゲート欠落、DFS取得日時・費用・鮮度は詳細へ分離する。
カテゴリーは親/子/孫を別列・別連動フィルターとし、サイト内に存在しない深度は列とフィルターを自動非表示にする。
POの統合・分割・除外は追記証跡として機械判定より優先する。
