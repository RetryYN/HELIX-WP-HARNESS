# 非一意URLの関連付けへの影響

## 読取り専用PoC

既存の保持データを使い、ページ・キーワードグラフを同じ関数で再計算した場合と、
伏せ字URLを共通ページの根拠から除外した場合を比較した。DBはこの比較では変更しない。

- ページ・キーワード接続：919件 → 850件。
- 共通ページを持つキーワード組：804組 → 347組。
- 457組は識別可能な共通ページが残らなかった。無関係と証明したわけではない。
- 同じgroup内の7組が `merge_supported` → `merge_recheck`。
- 別group間の7組が `separate_with_internal_link` → `separate_supported`。
- 複合境界判定の統合合意候補は1組のまま。レビュー対象集合は74組 → 75組。

これらは観測範囲内の判定材料と判定の変化であり、意味分類精度やランキング効果ではない。

## 要求と実装

非一意の `<redacted-...>` を同一ページの識別子として使わない。
評価画面とグラフ生成は共通の識別判定を使い、リテラル・URLエンコードされた伏せ字を扱う。
安定した匿名ドメインまで一律に除外しない。

グラフから除いた観測は `identity_exclusions` にtask・順位・元URL・理由を残し、
DB構築時には `serp_url_identity_exclusions` metadataに保存する。
元の検索結果・raw payloadは削除しない。グラフのページ数・ドメイン集計は
識別可能なページ接続の範囲になるため、検索結果全体の網羅的な件数とは解釈しない。

人工データの回帰テストで、同じ伏せ字だけの2taskから接続・関連組が生まれないこと、
安定した匿名URLの共通ページは保持されること、除外記録と入力原本が保たれることを確認する。
実DB統合テストの期待値も、全URLではなく識別可能なURLを正本にする。

## 運用上の残件

候補DBの再構築・検証後、ローカル稼働DBへ反映済み。旧DBは復旧用に保持する。
raw payload 110件は内容まで一致し、キーワード10,694件、生成候補765件、
レビュー記録、fingerprintと分類候補、累計費用記録は保持された。
73件の元観測を識別不能として記録し、重複排除後の69接続がグラフから外れた。
DB整合性・外部キー・関連API3経路を確認した。変更後の全183項目再実行ではない。

最初の候補構築は既定の追加取込設定が稼働DBと異なり失敗したため、切替対象にしなかった。
稼働DBのmetadataに合わせ、追加取込を無効にし、累計費用台帳の読取りは維持して再構築した。

今後もコード変更だけでは構築済みDBの関連付けは更新されない。稼働中DBの一貫したコピーで
候補DBを再構築し、raw payload・レビュー記録の保全と下流の判定変化を確認してから切り替える。
過去のグループ割当を自動的に書き換える修正ではない。既存グループや別経路のURL結合、
意味分類精度の監査は引き続き必要。
