# キーワードの意味整理から記事ストーリーを構成する再設計

## 実機で確認した問題と要求

保持DBには検索需要の出現1,188件、識別可能URLのエッジ850件、意味レビュー63件がある。
既存の構成生成は語の重なりで選んだ質問を順位順に並べ、先頭だけH2にしている。
意味グラフの上位概念には文脈に無関係な語も入り、同じ課題の証拠にはならない。
3記事の手作業編集を生成器の品質証明とはしない。

目的は見出しの言い換えではなく、キーワードが表す読者状態・課題・解決後の変化を
根拠付きで蓄積し、その関係から記事の範囲とストーリーを導くこと。

## 入出力と判定

1. キーワードごとにSERPページ、PAA、関連検索、語義・類語・想起候補を束ねる。
   原本ID・観測時点・語義経路・元のキーワードを保持する。欠測と観測ゼロを区別する。
2. 意味解釈は、読者の状況、検索のきっかけ、既知事項、疑問、障壁、望む判断・行動、
   解決後の疑問を持つ。各解釈に根拠ID・推論理由・代替解釈・未確認事項を持たせる。
3. 同じ語でも複数の読者・目的を保持する。類語辞書だけで語義を確定しない。
4. ペア関係はsame_problem / prerequisite / next_question / alternative / separate / unresolved。
   SERP一致を裏付けの一つとして使うが、一致率だけでsame_problemにしない。
   PAAの表示順、再帰取得順、関連検索への掲載をユーザーの行動順と呼ばない。
5. 同じ読者の同じ課題を同じ回答で解決できるものを記事候補として統合する。
   A-B、B-Cの類似だけでA-Cを自動統合しない。矛盾する読者・目的・時点を残す。
6. prerequisite / next_questionを使い、想起→理解→比較→障壁解消→判断・行動の
   状態変化を記事内の節または別記事への接続として構成する。全記事に同じ段階を強制しない。
   遷移には「何が解決すると次の疑問が生まれるか」を必須にする。
7. タイトル・見出し生成はこの意味構造を入力とする。未解決の解釈を語の羅列で埋めない。

## 実装と終了条件

### 上位記事との外部照合（追加要求）

意味整理後の課題集合を、同じ検索条件・観測時点の上位記事の見出しの意味単位と照合する。
語の完全一致ではなく、解決する疑問・対象読者・到達状態の対応を根拠付きで記録する。
さらに1位記事の正確なURLに対応する観測済み獲得キーワード集合と照合し、共通需要・
不足需要・別目的の混入を区別する。ドメイン全体の獲得語を1記事の獲得語に代用しない。
取得上限・地域・言語・端末・日時と、未取得の見出しや獲得語を明示する。
同じ上位記事から解釈を作り同じ記事だけで検証すると循環するため、保持外の語や別時点でも確認する。

これは内容側の需要充足を検証する指標であって、検索1位の十分条件ではない。
順位は内容以外の信号にも依存するため、順位達成は公開後の別検証に分ける。
参考：https://developers.google.com/search/docs/appearance/ranking-systems-guide

一つの再設計単位で、証拠集約→意味解釈→統合・遷移→記事構成→画面を接続する。
既存DBと原本を保持し、候補DBで検証してから切替える。取得APIへの追加課金は行わない。
最初の証拠集約モジュールだけでは完成としない。手編集した3件の固定テンプレートも不可。

終了条件：実データで根拠から解釈・統合理由・遷移理由・記事構成を追跡でき、
同義異表記、同語異義、別読者、前提関係、循環、欠測を試験し、独立レビューで内容を評価する。
検索者の実際の心理・遷移の実測とは区別する。旧見出し案の自己採点で完了率を増やさない。

## 現在の実装範囲

証拠集約、編集仮説の検証と完全連結条件による課題統合、遷移の循環検出、別DB保存、
確認HTML、記事内質問と内部リンク質問の振分け、課題単位の記事設計を実装した。
意味仮説そのものの生成はまだ編集作業であり、全体への自動意味付けを実装済みとはしない。
保持SERPの100タスク中11タスクに76解釈・35課題候補を作成したが、元の全キーワード数に
対する処理完了率ではない。独立品質評価、残タスク、獲得キーワード照合、既存画面への統合は未完了。
公開リポには処理と合成テストのみを置き、実データ・編集判定・派生DBは同期しない。
回帰テスト：`npm run research:keyword-meaning:test`（追加課金なし）。

見出しの比較準備はH2〜H6を保持し、H1を含む親見出しの文脈を付与する。
同名の見出しを文字列だけで統合せず、ページと位置で識別する。本文領域・意味的一致は別の確認事項。
経験を発見する方法と経験を選ぶ課題を分離し、確認HTMLでは方法・得たい材料・根拠も表示する。
別の上位記事で不足を見つけて補完した場合、その記事を独立検証済みの証拠には使わない。
回帰テスト8プログラムは標準の `npm test` 経由で実行し、固定されたCIステップ構成は変更しない。
