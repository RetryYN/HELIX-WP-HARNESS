# SEO分析PoCの納品整理

## 目標と進捗

全機能を調査し、それを超える分析機能を実現する最終目標は変更しない。
現行35項目の監査記録は検証済み6・未完了29で、目標進捗の指標は **17.1%**。
これは現在の機能監査リストに対する割合であり、未知の機能や優位性まで証明した割合ではない。
PR数・テスト数・コード量を完了率に換算しない。PoCの区切りと最終目標達成を混同しない。

## 納品までの一本道

1. 実行中のURL識別修正を候補DBで検証する。原本・レビュー記録の保全を確認できれば反映する。
   失敗したら稼働中DBを維持し、原因を残す。修正の連鎖を新規調査へ拡大しない。
2. 既存画面で「キーワード選択 → 関連証拠 → タイトル・見出し候補 → 出力」を通して確認する。
   ルール生成と実LLM生成を区別し、未実行のLLMを実装済みの品質として見せない。
3. 既存PR群を一つのリリース単位として整理し、現headレビュー・main向けCIを満たして反映する。
   小項目ごとのPR新設は止める。履歴改変・無審査マージで短縮しない。
4. 使える成果・既知の制約・未実装をまとめてPoCを引き渡し、次の投資判断を求める。

DB修正の区切りは完了：候補DBの整合性、原本内容とレビュー記録の保全、関連APIを確認し、
ローカル稼働DBへ反映済み。旧DBは復旧用に保持。次は既存画面の一連操作と変更の反映確認。

画面の一連操作も専用Chromeで確認済み：キーワード一覧の検索、対応するタイトル候補・
見出し8件の表示、コンテンツ設計ビューのJSON保存を実行し、表示と出力内容が一致した。
63設計カードが表示され、ページの実行例外・外部HTTP・書込みリクエストは0だった。
これは保持データとルール生成候補の操作確認であり、実LLMの生成品質を評価したものではない。

## 残件の分類

| 区分 | 対象 | この区切りで必要な証拠 |
| --- | --- | --- |
| PoC必須 | DB取込・原本保持・伏せ字URLの誤結合防止 | 保全比較、修正箇所の回帰テスト、候補DBの整合性 |
| PoC必須 | キーワードからタイトル・見出し候補までの操作と出力 | 一連の画面操作。取得不足・生成方式・未承認を明示 |
| PoC必須 | 既存変更の反映と公開情報保護 | 最終レビュー、CI、公開情報検査、ローカルAPI接続限定 |
| 精度改善 | 意味分類・同一記事判定・時間軸や読者の違い | 独立した評価。現状は未検証であり自動統合しない |
| 精度改善 | 実LLMのタイトル・見出し品質 | 予算配分確認、実行結果、既存候補との内容比較 |
| 後続機能 | 取得範囲拡張、深い質問探索、順位履歴、外部データ連携、残る機能同等性 | 各機能の契約と実データ検証。未完了29項目は削除しない |

## 既存変更の束ね方

- #234〜#241 は依存順に積まれた既存変更。未マージであり、個別完成を全体完成としない。
- #241をmain向けの統合レビュー対象として使い、#234〜#240の祖先commitを含めて一度に確認する。
  元PRとブランチの履歴は削除・書換えせず、統合対象の全変更パスをscopeに明示する。
- 現在のグラフ修正もこの納品単位に含め、追加の細分化を行わない。
- 既存PRは現在baseがmainでないものがある。ローカルテスト成功をmain向けCI成功と呼ばない。
- 新規機能・表示の微調整・検証資料の増設は、納品必須の欠陥でなければ後続へ送る。

## 予算と未確定事項

有料テスト上限は累計$5。追加有料実行は行わない。
生成テストへ最大$0.25を再配分する確認は未回答。全体予算の増額は提案しない。

レビューHTMLの存在や自動テスト成功は、意味分類精度の証明ではない。
